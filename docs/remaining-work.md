# 后续实验与建议分工

## 项目边界

本仓库只复现 Hilprecht 与 Binnig 的 VLDB 2022 Zero-Shot Cost Models 论文。
与同目录下另一个 Deep DB 论文复现项目完全独立：不共享虚拟环境、输出目录、Git 仓库或 checkpoint。
`data/runs/deepdb_augmented` 是 ZeroShot 作者发布的查询计划，附带 DeepDB 基数估计，是本论文三种输入设置之一；使用这些已发布估计不等于完成另一篇 DeepDB 论文的复现。

## 还没有完成的内容

1. **完整训练与留一数据库实验**：当前短训练只证明流程。使用全部可用源查询、官方训练预算（至多 200 epochs，验证集早停 patience=20），轮流保留测试数据库；多个种子报告均值及波动。不要把 `--epochs 200` 的单次 IMDB 实验称为整篇论文复现。
2. **完整查询泛化实验**：JOB-light、synthetic、scale 之外，还需要 parsed_plans 中的复杂查询和完整 JOB 工作负载。先固定各表/图的数据切分与统计范围。
3. **基线与消融**：核对论文的 PostgreSQL、工作负载驱动模型、few-shot、训练数据库数量、查询复杂度、数据/工作负载漂移等比较。必须分别记录基数来源；exact cards 使用真实基数，只是理想化实验设置。
4. **原始采集与 DeepDB 注释链路（若课程要求）**：目前直接使用作者的预处理计划；尚未重新导入关系表、搭建论文版本 PostgreSQL、执行查询、训练基数估计器并重新生成注释。需要大量时间和磁盘，结果受机器与数据库设置影响。这些操作也只属于本 ZeroShot 实验，不引用另一个项目的完成状态。
5. **论文数值核对与报告**：把每张拟复现图表对应到数据、种子、配置、结果文件和误差定义，记录与原文的差异及原因；完成结果图、报告和演示。
6. **批处理不变性审计**：同一 checkpoint 在上游随机测试批次下，少数预测出现差异；目前固定测试顺序并严格验证重载一致性。正式实验前进一步检查图合并、特征共享及浮点运算，验证不同 batch size/组合下的预测差异，不能把固定批次可重复误称为批次完全无关。

## 四人分工建议

| 负责人 | 工作 | 交付与验收 |
|---|---|---|
| A：数据与实验协议 | 核对论文设置、数据清单、留一数据库划分、预处理统计范围；需要时维护 PostgreSQL 数据采集 | 冻结实验配置、数据哈希、无训练/测试泄漏的检查结果 |
| B：模型与完整训练 | 维护环境兼容、三种基数输入的完整训练、多种子、checkpoint 和资源预算 | 每次运行的配置、日志、模型、验证集选择依据、逐查询预测 |
| C：基线与扩展实验 | 复现基线、few-shot、消融与复杂查询泛化；与 B 使用一致数据划分和指标 | 可运行基线脚本、对照结果、统一 Q-error 评估 |
| D：核验与报告 | 独立复算指标、核对原文表图、汇总不确定性与限制、绘图及撰写报告 | 可追溯结果表、图、复现差异说明、最终报告/PPT |

三人组可合并 A 与 D；两人组可由一人承担 A+B，另一人承担 C+D。先由全组确认目标图表与预算，再并行工作。以上只是分工建议，未邀请或通知任何协作者。
